# Flockdeck v0.9.3

This release reworks the Conversation tab of a structured pane. The layout is simpler, the prompt box takes pictures, and prompts and replies can show pictures.

## Layout

- One header strip replaces the stack of bars above the log. Export, cost and counts are in the More menu.
- The log fills the full height of the drawer and has one scroller. Popovers are no longer clipped by it.
- The log keeps following the bottom when the drawer is resized.
- Rows no longer carry speaker labels. The time is at the foot of the row.
- A prompt that failed has Retry, and long rows have Show all and Copy.
- Notices have a tone, so a refusal and a plain message do not look the same.

## Prompt box

The prompt box is one bordered composer: pictures on top, then the text, then one row of controls (Attach image, `@`, `/` and a button). Under it is one status line. Before, several notes could stack there. Now the most urgent one shows: a refusal or failure first, then a warning about a picture, then a hint.

The button is Send. While the agent works and the box is empty it becomes Stop. With text in the box it reads "Send (queues)", and the text goes to the queue of waiting prompts.

Stop no longer drops the queue. The waiting prompts stay, as they do with Escape and Ctrl+C. Clear in the queue list drops them.

## Pictures in a prompt

Paste a picture, drop one anywhere on the drawer, or choose it with Attach image. Each becomes a chip next to the text with a thumbnail, name, size and a remove button. A prompt takes up to 4 pictures. The window scales each one to under 600 KB (a PNG stays a PNG when it fits, otherwise it becomes a JPEG).

Pictures are sent to the agent as real ACP image blocks after the text. Nothing is written into the text any more. A prompt can have pictures and no text. If a picture fails, its chip says so and the others carry on. Send waits until they are done and is held while a failed chip is still there.

An agent that did not say it takes images at startup refuses them. The window shows "This agent does not take images" and sends nothing. Attach image is dimmed for those agents and says why when pressed. A window reached through the relay has none of this.

In the log, a prompt's pictures show as thumbnails, and a click enlarges one. Uploaded pictures are kept for 7 days. After that the row says "No longer available". A prompt waiting in the queue shows "+N images".

## Pictures from the agent

When an agent returns a picture in a message or a tool result, the log shows it. Only png, jpeg, gif and webp are drawn. A picture over 700 KiB is dropped, as are pictures past 4 for one tool call. A refused picture leaves no entry and no error. If the window has dropped the bytes of an old picture to save memory, the row says "No longer available".

## Retry

Retry shows only on prompts you typed, and not on one that had pictures. A failed prompt is not kept with its pictures, so you attach them again.

## Control socket API

The API is at version 1.33:

- 1.30: `paneSend` takes `images`.
- 1.31: notice entries can carry a tone.
- 1.32: prompt entries are marked as typed.
- 1.33: `attachImage` takes a `req` and the result echoes it, so several pictures can be matched to their chips.

There are limits on the desk side. A prompt's pictures are 5 MB each and 8 MB in all, and the waiting prompts hold 16 MB between them. A window may send 6 `paneSend` calls with pictures in 10 seconds.

## What was and was not tested

The Go tests for the touched packages and the whole UI suite (1,962 tests) passed. Nothing was run against a real browser, a real agent that returns pictures, a screen reader or an input method editor. The layout was only checked in static renders. A failed turn still drops the queued pictures. A window in the watcher role can read the pictures of prompts.
