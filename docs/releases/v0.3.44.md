# Flockdeck v0.3.44

## Panes no longer show as working when nothing is happening
After a restart, every restored agent could read as working, and switching
projects did the same, because the redraw an agent does on resume or on a
window resize was taken for work. Green badges, "N working" in the top bar
and the rail badges then claimed work that was not there.

- A Claude Code pane now hands its status to its hooks as soon as its session
  starts, and is idle until they say otherwise.
- Output that follows Flockdeck's own resize or repaint, with nothing typed,
  no longer starts a working status.
- A pane's first screen is not counted as work: a restored pane comes up
  starting, then idle.
- Real work is still shown. Output that goes on past those short windows
  marks the pane working.

**Limitations:** an agent whose hooks never report is still read from its
output, so it can still show working when it is not, though less often. A
command started in a pane that prints for under about 5 seconds shows
starting, then idle, and never working.

## Worktrees and changes behave better
Six fixes to worktrees and the changes list, which matter when agents work
in isolated checkouts:

- A failed worktree add no longer leaves its new branch behind. Before, a
  retry from a different base found that branch and started from the wrong
  commit.
- A project opened at a subfolder of a repository, such as one service of a
  monorepo, now gets its new worktrees beside the repository rather than
  inside it, where the main checkout listed them as untracked.
- `flockdeck spawn --worktree` no longer reuses a worktree whose folder was
  deleted by hand. The branch is refused with the existing message that says
  to use Prune.
- A branch named like a tag, such as `v1.2` beside a tag `v1.2`, is now
  listed, checked out and pushed under its own name.
- A file renamed in the working tree is now one entry in the review panel
  instead of a phantom file, and is committed as a rename.
- Removing a worktree now waits for a `flockdeck spawn --branch` that is
  starting a helper in it.

## The built-in chat client asks before running more
Choosing "always" for a command covers its first two words. These calls
slipped past that and ran on an earlier "always"; they are now asked about:

- `git difftool -x`, in any spelling, and `git filter-branch`.
- `npm` with `--script-shell`.
- `go env -w`. Reading `go env` keeps its permission.
- `npm.cmd`, `npx.cmd` and other `.cmd` or `.bat` spellings, which are now
  judged by their name like `npm` and `npx`.
- On Windows, a command whose second word is a `/` option, such as
  `schtasks /create` or `msiexec /i`.

## Remote access
- A failed **Move** to another relay no longer leaves the new registration
  behind when it ran out of time, which showed every device an offline host
  that nothing held.
- End-to-end encryption no longer falls back to plaintext when the device
  list is momentarily stale or cannot be fetched. Before, a terminal could be
  served unencrypted, and the browser's handshake bytes typed into the pane.
- Email verification now works on a machine whose clock is ahead of the
  relay's. Before, it could time out before its first check.
- Moving to another relay is now refused from a relay window; it can only be
  done at the machine itself, as turning remote access on or off already was.
- A phone that disconnects while opening a chat is no longer left showing as
  viewing it.
- A push delay so large it wrapped around is now refused instead of saved.

## Linux self-update works
The updater picked the `.deb` package instead of the `.tar.gz` archive and
failed to unpack it, so no Linux install could update itself. It now takes the
archive. An install already on an affected version has to be updated by hand
once to get this fix.

## Web UI fixes
- Closing Settings while recording a shortcut no longer leaves the window's
  keyboard swallowed.
- A release-notes heading containing a Unicode line separator no longer hangs
  the update dialog.
- After one good connection, a terminal that loses its connection now backs
  off between retries instead of retrying every 250 ms for the whole outage.
- Saving a todo step no longer reopens the Todos dialog, or resets one that
  is open.
- Asking for the prompt bar while it is open keeps the text you typed.
- A failed version download no longer leaves its button on "Downloading…".
- The agent overview tabs, and the remote move form, keep the keyboard after
  you use them.
- The GitHub create form no longer waits forever after a dropped connection.
- The prompt bar's label counts the pane the prompt is going to, not the pane
  in focus.

## Smaller fixes
- The rail's collapse button now says **Widen the rail** or **Narrow the
  rail** to match its state, and the logo lines up with the icons when the
  rail is widened.
- The Routing rules row in Settings no longer squeezes its description into
  one word per line beside a long rule. This was tested without a browser, so
  it has not been checked by eye.
- The recent-projects list no longer drops the project in use when it is
  full.
- A transcript image that is a tiny PNG claiming a huge size is now refused
  instead of exhausting memory.
- A large MultiEdit no longer loses its status event.
- A corrected Jev key is no longer held back by the old key's cooldown.
- The hook and status line command now survive an install path with a curly
  apostrophe, as in `O’Neil`, on the PowerShell path.
- In a project with several repositories: closing a repo's last tab, cycling
  tabs, reordering or merging tabs across repos, **Merge all tabs**, and going
  to a repo with no tabs of its own now all keep a tab active and keep the
  active repo in step with it.
- Agent settings saved while agents were being checked, such as a new default
  agent, now take effect straight away instead of up to a minute later.
- A stale answer to a changes, worktrees or conversations request can no
  longer replace a newer one.
- Two data races on a pane's auto-approved count and peer name are fixed.
- Tests no longer open a real browser, and the docs automation now writes its
  stamp.

## Go module
Releases v0.1.0 to v0.3.30, published under the MIT License before the
relicense, are now retracted in the Go module, so `go get` and `go list` stop
offering them. This does not remove them, and it does not withdraw the MIT
grant for copies already taken.
