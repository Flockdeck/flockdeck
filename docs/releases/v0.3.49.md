# Flockdeck v0.3.49

## A stuck "in background" count now corrects itself
**If a pane kept saying "N in background" after the work had finished, this
fixes it.** The badge counts what Claude Code's hooks report, and when a
report that something ended was missed, the count stayed until the next time
the agent stopped. An idle agent with a stuck count also showed as working.

- **Flockdeck now checks.** An idle Claude Code pane that has background work
  is checked against the conversation Claude Code stored for it, first after 45
  seconds, then less often (up to every 8 minutes) while the checks find
  nothing. It reads files on your machine only.
- **Work is dropped only on evidence:** a finished task notification, a
  TaskStop or KillShell that succeeded, a subagent handing its result back, or
  a monitor that has run past its timeout. The tooltip lists work that ended
  this way for two minutes, with the evidence.
- **Work with no sign of running for 30 minutes stays counted but is marked
  unverified**: the badge reads "N in background, unverified". An idle agent
  whose background work is all unverified no longer counts as working, so its
  dot and tab go back to idle. The pane is still not closed as finished while
  the work is counted. There is no button to clear the count.
- **The badge's tooltip now lists the work**, up to 8 items: its kind (shell
  command, subagent, monitor, workflow), the description and command Claude
  Code gave, and when Flockdeck first saw it. Text that looks like a secret is
  hidden, but file paths are shown as typed. The same list is on the agents
  list and in the phone and browser views.
- **A task notification is read the same way on both paths**, the live
  hook and the check of the stored conversation. It counts only when the
  message is exactly one well-formed block with the task id first and a
  finished status (completed, stopped, killed, failed, cancelled or error).
  A message that holds two notifications ends neither task, and those tasks
  are settled at the next stop. A monitor event, a running status, or text
  that only mentions a notification ends nothing, and text a command prints
  cannot end another task. In the stored conversation, a user turn also has
  to be marked by Claude Code as a notification.
- **One limit remains on the live hook path.** Hooks do not say who wrote a
  prompt, so a prompt you type that is itself exactly one well-formed finished
  notification can still end its task. The next stop's list of background
  tasks puts it back.

**Not changed:** the count still comes from Claude Code's own reports, and
Flockdeck cannot tell whether a shell command that prints nothing is still
running. Only Claude Code panes are checked.

## Pane info and Find pane
There was no way to see a pane's id. **Pane info** lists what names a pane in
files, logs and commands, one row each with a Copy button, and **Copy all**.
Open it with the `ⓘ` button in a pane's header, **Pane info** in the command
palette, or `Ctrl+Shift+Y`.

- **What it lists:** the pane id (which `flockdeck close` takes), name,
  project, project folder, directory, branch and tab; for an agent, the agent,
  model and conversation id (the first 8 characters are in a transcript's file
  name); the process id, peer name, status, whether it is recording, its
  transcript file, and the file where the agent stores its own conversation.
  Anything the pane does not have yet says "not set". No keys, tokens or
  environment values are shown.
- **The stored conversation file is shown** for Claude Code panes and for
  Flockdeck's own API agents, once the agent has written it. A new API agent
  pane that was never prompted has no file, and says "not set".
- **Find pane** (`Ctrl+Shift+L`, or in the palette) searches every pane in
  every open project by name, project, tab, agent, model, directory, branch,
  pane id, conversation id, process id or peer name. Several words must all
  match. A conversation id matches from its first characters. Enter opens the
  first result, a click opens any; it switches to the project and tab and
  focuses the pane. Enter does nothing until the results shown are for what
  the field says, so typing fast cannot open a row from the previous search.
- If a pane closes while Pane info is loading, it says the pane is no longer
  open.
- Both views work only from the machine Flockdeck runs on. A window reached
  through remote access is refused with a notice.

## More in transcripts
Transcripts (exports and live recordings, which share one code path) carry more
of what Claude Code stored for the conversation. All of it is optional, written
only where the stored conversation has it, and the format stays at `v: 1`.
`docs/recording-format.md` has the details.

- **`model`** is back on `assistant_message` and `tool_call` lines: the model
  that produced that turn, so a conversation that switches model has each
  turn's own. It is never the model the pane is set to now.
- **`usage`** (`inputTokens`, `outputTokens`, `cacheCreationInputTokens`,
  `cacheReadInputTokens`) and **`stopReason`**. Claude Code stores one reply as
  several entries that repeat the same numbers, so each is written once per
  reply, on its first line, and you can sum `usage` over all lines. This is
  exact only while a reply's entries agree, which was so in every real
  conversation checked.
- **`gitBranch`, `cwd` and `agentVersion`** on every line that comes from a
  stored entry. **`cwd` is a full path and usually contains your account
  name.** Redaction looks for secrets, not names. Before sharing a transcript,
  run for example `jq -c 'del(.cwd)'`.
- Two new line types: **`conversation_title`** and **`conversation_compacted`**
  (with `trigger`, `tokensBefore` and `tokensAfter`). The text of the summary a
  compaction writes is still not recorded.
- **Files already written do not change.** An export made before this release
  has none of these fields unless you export the conversation again, and they
  still read as before. No field says which version wrote a file; a file with
  any of the new fields is newer, and a file without them proves nothing.

## Wording corrected
A pass over the text in the window and the Help pages, checked against what the
code does. A few of these say something different from before:

- The first-time recording prompt says a transcript stops at 16 MiB and that
  recordings older than 30 days are deleted (the oldest go sooner once a project
  has over 100 files or 256 MiB). It named only the 30 days.
- Tooltips and notices that overstated: Export and Record say only Claude Code
  has a conversation Flockdeck can read; Lock says it also keeps the project
  from closing; Auto-review no longer says "Off by default" outright, since
  Settings can turn it on for new panes; Close finished panes leaves panes with
  background work and locked panes open.
- The in-app Help pages and `flockdeck` usage text were corrected to the
  current Settings layout, recording and export behaviour, routing and shortcuts.
  The README and docs were corrected the same way, and em dashes and filler were
  removed from the app's text, Help pages, CLI messages and README.

## Nothing else changes for you
This release also fixes seven tests that failed at random and changes the
website and docs. None of it changes anything in the app.

Update if a pane's "in background" count gets stuck, or if you read transcripts
with a script and want the new fields; otherwise nothing needs doing.
