# Flockdeck v0.4.0

This release changes the format of transcript files in a way older readers cannot use, so it moves to 0.4.0. It also adds batons, the conflict radar and helper apps, renames Remote access to Flockdeck Remote, and changes what turning Flockdeck Remote off does.

## What to do when you update

- Recordings and exports now use format version 2. Files already on disk are version 1 and are not read by tools that expect version 2. `flockdeck recordings` still lists them. Export a conversation again to replace its old export. A script that reads transcripts needs changes, listed under "Transcripts are now format version 2".
- Flockdeck Remote is the new name for Remote access, in the window, the Help pages, the README and the command-line messages. Searching for the old name in the palette, in Settings and in Help still finds it. Commands, flags and config keys keep their names.
- `flockdeck remote disable` and the Turn off button now keep your account on the relay. To take only this desktop off the account, use `flockdeck remote remove`. Scripts that ran `disable -force` should run `remove -force -yes`.
- If you turned Flockdeck Remote off with this version and later go back to an older Flockdeck, the older one ignores the off setting and reconnects. Turn it off with the version you turned it off with.
- Enabling Flockdeck Remote or moving to another relay can now ask for a match code (see below). If you script `flockdeck remote enable` against a relay that verifies email, run it once by hand.
- The conflict radar is off. Nothing about batons or the radar changes until you use them.

## Transcripts are now format version 2

Transcripts are the files a recording or an export writes. The format is described in `docs/recording-format.md`, and a JSON schema next to it now checks every line.

- Every line has `"v":2`. A reader that checks `v` will refuse files from earlier versions, on purpose.
- The `pane` and `paneName` fields are gone. `pane` always held the same value as `conversation`, and `paneName` was never written by the current code, so readers got null.
- The line types `session`, `permission_prompt`, `permission_outcome` and `status` are gone, along with the fields only they used. Nothing has written them since v0.3.48.
- `agent` and `conversation` are required on every line. The `recording_truncated` line now has them, which it lacked before.
- Start, stop, truncation and title lines carry `gitBranch`, `cwd` and `agentVersion`, as other lines already did.
- `isError` and `interrupted` are written on every `tool_result`, as true or false. Before, they were written only when true.
- Each of the four `usage` counts is written only if the stored conversation has it. Before, a missing count was written as 0, so 0 could mean unknown.
- The schema is strict: each line type lists its own fields and nothing else is allowed.
- `flockdeck recordings` lists the first 8 characters of the conversation id where it used to show the pane name, which was empty for every current file. `-json` has `conversation` and no longer has `paneName` or `model`.

Exporting a conversation again now replaces its earlier export. Before, the new file was dropped with "nothing new was written" whenever the older one lacked the title lines v0.3.49 added, so an export made by v0.3.48 could never be refreshed. The new file is written beside the old one and moved into place only when it is complete, so a failure does not lose the old export. The window and `flockdeck recordings export` say "replaced", or "not up to date" when the old file has events the new one lacks and is kept.

An export now runs off the window's main loop. Before, exporting a 25 MB conversation held the server for about a second. Asking again from a second window while one export runs waits for it and gets the same notice.

## Batons: hand work from one agent to another

A baton is a short markdown document one agent hands to the next: what the work is for, where it stands, the files that changed, the commands that were run and what must hold. Any agent can be started from one, whichever agent wrote it. Nothing makes a baton on its own. One exists only when you run Make baton or an agent runs `flockdeck spawn -baton`.

To make one, run Make baton from the command palette with a pane focused. A draft opens for you to edit. Files touched come from git, and commands and tests run come from the agent's stored conversation, with repeats collapsed and failures kept. Where things stand quotes the agent's last message. Decisions, open questions and constraints are left empty for you to fill in, and a section left empty is not sent. Only Claude Code and Flockdeck's chat client keep a conversation Flockdeck can read. For other agents the draft is built from git and the task.

The footer of the draft has three choices. New pane starts an agent from the baton in a tab of its own or beside this pane, in this checkout or in a new git worktree on a branch you name. Restart this pane ends the pane's conversation and starts a new one in the same checkout from the baton. Save only keeps it for later. If the new agent belongs to a different company than this pane's, or Flockdeck does not know whose it is, the dialog asks you to tick a box first, because the baton is sent to it.

Agents can do the same from a terminal, for example `flockdeck spawn -worktree fix-auth -baton self "Finish the auth middleware"`. `-baton` takes `self`, a pane id of the spawning pane's project, a baton id, or `path:` and the path of a notes file (`.md`, `.markdown` or `.txt`) inside the project or checkout. `flockdeck baton list` lists stored batons and `flockdeck baton show` prints one, or with `-path` the file it is kept in.

Two Help pages cover this: Handing work to another agent, and Baton details, which has the long lists (what the scrubber takes and misses, how an agent's company is decided, and how batons are kept and removed).

- The scrubber is a filter and not a guarantee. Before a draft is shown, and again on the text you send, it replaces what looks like a secret with a mark such as `[REDACTED: aws-key]`. It redacts when in doubt, so it also takes some text that is not a secret, mostly in code, and it misses some secrets: short ones, ones that are a word, and ones not named as secrets. Read a draft before you send it.
- Counted against every line, the scrubber changes 0.3% of the non-test Go source of `net` and `crypto` in the Go 1.27 standard library and 0.9% of this repository's `app.js`. Counted only against lines that contain `key`, `pass`, `pw` or `pwd` anywhere, it is 2.6% and 14.2%.
- A baton for an agent of a different company, or of one whose company Flockdeck cannot tell, is refused unless the command has `-baton-send-elsewhere`. With the flag the agent only asks: a notice in a Flockdeck window on this machine names the pane, the destination and the baton's size and first line, and has a Send it button. Nothing starts until you press it. If no window is open, or nobody answers within 45 seconds, the baton is not sent.
- That approval stops a mistake and a request nobody saw. It does not stop a program running as you, which can read the window's token from the state directory and press the button.
- A paired phone or other relay window can make, save, start and send batons. It cannot skip the approval: a start from a relay window that would go to a different or unknown company waits for the same notice on this machine whether or not the tick box was ticked, and is refused when no window here is open.
- Hidden Unicode (tag characters, fillers, format controls) is stripped from batons, and the fence the baton is wrapped in is hardened against lookalike characters. A few bits can still ride between non-ASCII characters.
- A notes file is read only from a local drive and only from inside the project or checkout of the pane that asked. Symbolic links, pipes, UNC and device paths, and network drives are refused.
- The whole build has a budget of 5 seconds. A text not begun by then is replaced by `[REDACTED: too-large-to-scrub]` and never passed on, so a very large conversation loses text, not secrets.
- Batons are kept in Flockdeck's state directory and removed after 30 days unused, with rules that keep any baton a saved layout names.
- A baton has no drafter, so the sections that need a decision are written by you. A baton does not carry uncommitted changes: a new worktree starts from the branch, and the dialog warns when the pane has uncommitted files. There is no picker for starting several agents from one baton at once.
- The company check reads Claude Code's, Codex's and Gemini's own settings for a different host. A settings file that exists and cannot be read, is over 1 MB or cannot be parsed makes the company unknown.

## Conflict radar

When two panes in the same repository have changed the same files, the conflict radar asks git whether their work would merge. If git says it would not, the header of each pane shows a chip naming the other pane. Hover it for a summary. Press it, or tab to it and press Enter, for a list of each other pane, its branch and the files git stops on, up to five panes and twenty files each.

The radar is off by default. Turn it on in Settings, General, Conflict radar. It needs git 2.38 or later, and on an older git the switch is dimmed and says so.

- It copies each checkout (committed, uncommitted and untracked files) into a throwaway object store in the system's temporary folder and has git merge the copies in memory with `git merge-tree`. It writes no file, index, lock or branch of a checkout. Git itself may set the modification time of an object file it finds already stored. A clean filter such as Git LFS runs on the copies and may write its own files into the repository; that has not been checked.
- A chip appears after the same pair has conflicted on two refreshes at least five seconds apart. The check runs with the git refresh, about every 15 seconds, for the panes on screen.
- A pane whose changed files add up to more than 100 MB, or include one file over 25 MB, is not copied. One refresh runs at most 50 merges, and the rest follow on the next.
- A pane with uncommitted or new files is copied on every refresh, which costs about 11 git processes and is noticeable on a very large checkout. A checkout that keeps running long is skipped for 10 minutes, doubling to at most 120. Nothing in the window shows a skipped checkout.
- A chip is a prediction from the last time both panes were read, and no chip is not a promise. The radar skips panes that are clean, detached, or in the middle of a rebase, merge, cherry-pick, revert, am or bisect, panes with unmerged files, panes before their first commit and panes with more than a thousand changed files. A shallow clone whose history does not reach the base is not checked. A repository whose real base is none of main, master, origin's default or the main worktree's branch is measured from the wrong one.
- A merge that is clean can still fail to build, and the radar does not say so. On Windows a pane whose only change is a file with a path over 260 characters looks clean unless `core.longpaths` is set in the repository.
- Pane names, branches and file paths go to every open window, including a paired phone or other window reached through the relay, which sees up to 20 file paths for each pair and can turn the radar on and off. File contents are not sent.
- The radar has no Tell both action, no suggested merge order and no comparison with main.

The Worktrees Help page has the rest.

## Helper apps

A helper app is a small program that Flockdeck downloads, installs in its own folder, starts and stops for you. The first is lens, which reads agent session transcripts. Use Helper apps in the command palette or `flockdeck helpers list`, `install`, `start`, `stop`, `open` and `uninstall`.

- Install shows the name, version, source address and signature, and asks first. The release's manifest is checked against Flockdeck's release key, and the archive against the SHA-256 and size in it, before anything is unpacked. A release that is not signed is refused, and nothing overrides that.
- A helper starts hidden on a free port bound to 127.0.0.1, with a short list of environment variables and none of Flockdeck's tokens or API keys. Flockdeck restarts it up to three times in five minutes and stops it when Flockdeck quits.
- A helper is not sandboxed. It runs as you, and any account on the computer can reach it on 127.0.0.1 with no sign-in, because it has none.
- Helper apps are managed on the machine Flockdeck runs on. A window reached through the relay is refused.

## Flockdeck Remote

Flockdeck Remote is the new name for Remote access. It is an optional add-on that opens your own Flockdeck window on a paired phone, tablet or browser, through Flockdeck's relay. The desktop app is free and does not need it. The Help page, the README and the command-line messages now describe it that way.

- Turning it off keeps your account. Turn off Flockdeck Remote in the window and `flockdeck remote disable` stop this machine connecting and keep the token, host id, account, plan or trial, verified email and paired devices. Turning it on again reconnects to the same account and the same address, with no new sign-up, no email check and no new trial. A `remote.json` written before this release has no off setting and is read as on.
- `flockdeck remote remove`, and Remove this desktop from the account in the window, takes this desktop off the account and nothing else. The account, its plan, trial, verified email, paired devices and any subscription stay, even if this was the last desktop. The command lists what it removes and asks first, and `-yes` skips the question. `-force` forgets the enrolment here when the relay cannot be reached. The window has a Show a join code button first, for adding a machine back.
- `flockdeck remote delete-account` erases the whole account on the relay: every desktop, every paired device, the plan and the link between the verified email and the account. It shows the masked email address, the desktops, the devices and the plan, and asks you to type `delete my account`. A script passes `-yes -confirm "delete my account"`, both together. An account with a subscription is refused, because deleting it does not cancel the subscription. The window does not offer this.
- The relay keeps an account while it is paid for, or while anything on it has been used in the last 90 days. Otherwise it deletes the account with its desktops and devices, without a warning. A desktop that enrolled and never connected is removed after 7 days, and only that desktop.
- When `flockdeck remote enable` or `move` has to verify an email, the relay can ask for a match code. The command prints it, such as `K7QM-42XD`, before the browser opens. The page that opens from the emailed link asks for it. The code is not in the email, so enter it only if you started this just now, and ignore the email if you did not. Too many wrong tries delete the registration, and the command says to run it again.
- On a relay that keeps one account for each verified email, `enable` and `move` add this desktop to the account that email already has, and say so with the desktop count and plan. Devices already paired reach this desktop too. A relay that does not do this makes a new account, as before.
- Refusals are clearer. A refused registration, a 429 with no explanation and a registration the relay has dropped each say what to do. The messages cover only what the desktop can see, because the page in the browser shows a rejected or blocked address itself.
- The window's Turn on still stops at a relay that verifies email, and says to run `flockdeck remote enable` from a terminal. It does not show the match code.
- The Free plan card says Flockdeck Remote through the shared relay is a subscription after a 30-day free trial.
- The privacy page now says the relay can keep a verified email address, and names the email provider it uses.

## Smaller changes

- Reveal transcript is no longer a button in every pane header. Pane info has a Show in folder button next to the Transcript file row. When it is off, the reason is given: the pane has not been recorded or exported yet, or the agent stores no conversation Flockdeck can read. Reveal transcript stays in the command palette.
- Close finished panes now says what it closes: idle agents and cleanly exited panes. It leaves idle shells, failed panes, locked panes and agents with background work open. Only the wording changed.
- Recording a key combination another action already uses is refused with a message naming that action. The Help page used to say it took the key.
- Recordings and exports use a redaction scrubber that batons share. Where two patterns match overlapping text, the whole stretch becomes one `[redacted]`. The word `bearer` or `basic` is skipped only under an authorization header name, so `password=basic` is redacted, while `Authorization: Bearer x` still keeps the scheme and redacts the credential. SendGrid keys (`SG.x.y`) are redacted by shape.
- The README is now a short entry point. Install, building, self-hosting, keys, architecture and agent briefing have their own pages under `docs/`, and the Help pages gained facts that only the README had. The README had said the tag alone cuts a release and that Codex, Gemini CLI, opencode and Cursor Agent start unbriefed. Both were wrong and are corrected.

## Fixes

- On Windows, the Changes window could rarely show "index file open failed: Permission denied" when `git diff`, `git status` and Flockdeck's own `git update-index --refresh` ran together. Each checkout now has a gate. The commands that read changed files never wait behind a refresh that is only waiting its turn, wait at most half a second for one that is running, and retry up to three times if refused the index. The refresh waits at most two seconds for them and does nothing if they do not let go. It never kills git and never removes an `index.lock`. After a refresh that failed or ran over ten minutes, a checkout is left alone for 10 minutes, then an hour, then six hours. None of this covers a git command run by another program, including an agent's own.
- `GIT_INDEX_FILE` is taken out of the environment of the git commands Flockdeck runs, since it would point them at an index that is not the checkout's.
- Helper app installs fail closed on a damaged `trust.json` and check the version rules again when installing.
- Several tests that failed at random were fixed. That changes nothing in the app.
