# Flockdeck v0.3.41

## Set the TypeSafe API key in Settings
The key for TypeSafe's Jev used to come only from the `TYPESAFE_API_KEY`
environment variable, which a desktop app started from a menu or the dock
often doesn't have. **Settings › Behaviour › Status detection** now has a
**TypeSafe API key** row where you can set, replace or clear it.

- The field is masked and starts empty. Flockdeck never shows the key back,
  only whether one is set.
- The key is kept in Flockdeck's local credentials file with owner-only
  permissions, the same store as your agents' API keys, not in the operating
  system's keychain.
- A key set in Settings is used first, then `TYPESAFE_API_KEY` from the
  environment Flockdeck runs in. No other variable is tried.
- A window reached through the relay cannot read, set or clear the key; do
  it on the machine itself.
- Saving a key sends nothing. **Status detection** and **Ask Jev to rate
  unmatched work** are still off by default and still gate everything Jev
  is asked, exactly as in v0.3.40.
- The key is only ever sent to `api.typesafe.ai`. It is no longer possible
  for an agent entry with the reserved id `@typesafe` to pick the stored key
  up as its own.

## The download server keeps access logs
The privacy policy on flockdeck.ai now says that the download server,
dl.flockdeck.ai, which serves the app, the installer scripts and the update
check, keeps standard access logs: the IP address, the path requested, the
time, the response code and the user agent. They are kept for 30 days and
stored privately, used only for security and for fixing problems with
downloads, and never for analytics. Flockdeck itself still has no analytics.
