## Auto-review stays on after a restart
**If you use auto-review, this fixes a setting that was silently lost.** A
pane's auto-review switch was not saved: after Flockdeck restarted, a pane came
back with auto-review **off**, even if you had turned it on, and even if "Start
new panes with auto-review on" was set. Panes restored after an update or a
crash, and conversations opened with *Resume a past conversation*, were the
same.

- The switch is now saved with the layout, on or off, and kept across a
  restart, an update and a crash. Turning it on or off saves the layout at
  once.
- A layout saved by an earlier version has no record of the switch. Its panes
  start from "Start new panes with auto-review on", which is **off unless you
  turned it on**.
- A pane opened with *Resume a past conversation* now follows that same
  setting, as every other pane you open yourself does.

**Not changed:** auto-review is still off by default, still covers Claude Code
panes only, and still decides the way v0.3.47 does.

## Export a pane's transcript, recorded or not
**Export transcript**, in the command palette and in a pane's header, writes the
whole conversation an agent has stored as a transcript file, **whether or not
recording was on**. `flockdeck recordings export <pane-or-conversation-id> [-o
file]` does the same from a terminal.

- **Only Claude Code stores a conversation Flockdeck can read** (the file under
  `~/.claude/projects` that *Resume a past conversation* uses). For Codex,
  Gemini CLI, Aider, opencode, Cursor Agent and the built-in chat, Flockdeck
  says so and exports nothing.
- **It asks every time**, saying what is written and that **it can contain
  secrets**. Redaction is best effort, as it is for a recording.
- **Where it goes:** the `exports` folder in the project's folder under the
  recordings folder, never into a project. `-o` writes to a path you choose,
  which must not already exist and cannot be inside the project or any git
  repository. An export deletes nothing.
- Entries over 8 MiB (a pasted screenshot, a very large tool result) cannot be
  read and are left out; the window and the command say how many.

## Recording is now made from the stored conversation
A recording and an export of the same conversation are **the same lines**: both
are built from the conversation the agent stored, by the same code, so a
recording no longer depends on the events the agent reports while it runs.
Recording is still **off by default**, and still asks the first time. **If you
read recordings with a script, read this.**

- **Recording starts at the beginning of the conversation.** Turning it on
  writes what has been said so far, then follows it. There is one file per
  conversation, named `<first event>-<conversation>.jsonl`; turning recording on
  again, or restarting Flockdeck while it is on, writes that file again rather
  than starting another.
- **Every assistant message is recorded**, including those between tool calls.
  v0.3.47 recorded the last message of each turn.
- **`status`, `session`, `permission_prompt` and `permission_outcome` lines are
  no longer written**, as a stored conversation does not record them.
- **`pane` is now the conversation's id**, and `paneName` and `model` are not
  written.
- **`time` is when the event happened**, from the agent's own record. The first
  and last lines now say `start of the transcript` and `end of the transcript`
  (they said `turned on` / `resumed` and `turned off` / `the pane was closed`).
- Subagents' own work and the entries Claude Code writes for itself (slash
  commands and their output, injected reminders) are not recorded.
- **Recording is now only for agents that store a conversation**, which today
  means Claude Code. Turning it on for any other agent is refused with a
  notice. In v0.3.47 it was allowed and wrote only a start and a stop.
- **The format version stays `v: 1`.** The shape of a line is the same, but a
  reader that relied on the lines above can no longer assume them.
  <!-- depends on #157 for the following paragraph and for the table in
  docs/recording-format.md it points to. -->
  **Recordings made by v0.3.47 are not changed and differ from new ones.** The
  file's first line tells them apart: `start of the transcript` is a new file,
  `turned on` or `resumed` is a v0.3.47 one. `docs/recording-format.md` lists
  every difference.

## Recording and export: fixes
<!-- depends on #157 (open). The whole section. -->
- A recording that cannot write no longer loses events without saying so: it
  starts the file again from the beginning, and after three failures in a row
  it stops and says why.
- A finished transcript is no longer cut short by being made again: the new one
  is written beside it and replaces it only if it has every line the old one
  had. If a program holds the old file open, the new one is left next to it as
  `<name>.jsonl.new` and Flockdeck says so; a stale `.jsonl.new` a day old is
  removed the next time a transcript is made in that folder.
- One conversation is one file: if its first event is now a different one, the
  earlier finished file of that conversation is removed when the new one is
  finished.
- **One pane at a time can record a conversation.** A second pane is refused
  with a notice.
- A tool's `output` is the text the agent was shown, not the tool's structured
  result, which could hold a whole file or an image as base64. No image data is
  in any line.
- **Exports are kept until you delete them.** Clearing out old recordings never
  touches them; the export confirmation and the help now say so.

## Reveal transcript
<!-- depends on #155 (open). The whole section. -->
**Reveal transcript** shows a pane's transcript file in your file manager with
the file selected: a button in the pane's header, an entry in the command
palette, and `flockdeck recordings export -reveal` for the file just written.

- It shows the file the pane is recording to, or else its newest export. If it
  has neither, it says so and points at Export transcript and Start recording.
  It does not show the agent's own stored conversation.
- Only from the machine Flockdeck runs on: a phone or other remote window
  cannot use it.

## Nothing else changes for you
This release also contains groundwork for later work that does not change
anything you can see or use.

Update if you use auto-review, or read recordings with a script; otherwise
nothing needs doing.
