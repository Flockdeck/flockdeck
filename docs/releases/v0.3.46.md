# Flockdeck v0.3.46

## Auto-review: a bypass is closed, and it checks more
**If you turned auto-review on, update.** Auto-review is off by default, and
this release does not change that; it only covers Claude Code panes. In
v0.3.45 and earlier, three things it approved without asking could go further
than it meant:

- **`go env --w`** was allowed, and Go accepts `--w` as `-w`. It rewrote Go's
  own settings file, for example to name a program for later `go build` and
  `go test` runs to start. Any `go` command could also make Go download the
  toolchain a project's `go.mod` asks for.
- **Quoted or escaped paths** such as `cat "/etc/passwd"` or `cat .\./x`
  were checked before the shell removed the quotes, so they could read a file
  outside the project and put its contents in the transcript, which goes to
  your model provider.
- **`git status`** could run a program. A repository can record a submodule,
  and an agent can write the submodule's git settings as ordinary project
  files; one setting (`core.fsmonitor`) names a program, and `git status`
  started it. An approved `git status`, `git diff` or `git describe` was
  enough.

Auto-review now:

- asks about any command with a quote, a backslash or a glob character
  (`' " \ * ? [`) in it;
- allows no `go` command at all;
- lets a `git` command through only when git, asked in the directory the
  command runs in, finds nothing configured that could run a program or reach
  the network: no fsmonitor program, external diff or textconv driver, filter
  (Git LFS's own is let through), gpg program, trace2 target or partial-clone
  remote;
- asks about `git status`, `git diff` and `git describe` whenever the
  repository has a submodule, and refuses `--submodule`.

A command that stops now reaches the ordinary permission prompt, as it would
with auto-review off. **The trade-off:** quoted commands that were fine, such
as `grep -rn "some text" .` or `cat *.go`, now ask. So does every `git`
command in a repository with a custom diff driver or gpg program, and `git
status` in one with a submodule. Nothing needs doing beyond updating.

**Not changed:** auto-review still covers Claude Code panes only, still uses
a fixed list and no model, and still sends nothing anywhere. Known and left:
a symlink inside the project that points outside it is followed, as Claude
Code's own read rules follow it; `git log -O<file>` and `wc --files0-from=<file>`
read a named file outside the project for ordering or counting, without
showing its contents; and the git check reads the configuration Flockdeck
itself sees, not one set only in a pane's own environment.

## One rule for what counts as working
Before, a pane, a tab, the top bar, the rail and the window title each decided
for themselves what "working" meant, and they disagreed: an agent between
turns with a command or subagent still running in the background had a
working mark on its pane, tab and project, but the top bar, the window title,
the favicon and the rail counts did not count it. They now come from one rule:
**an agent that is idle but has background work counts as working, everywhere.**

- The top bar's "N working", the window title, the favicon and the counts on
  the rail include it. A project whose only activity is background work shows
  a working mark and a count, not a mark with no number.
- A pane header and a project's rail badge show the working mark for it; the
  pane's tooltip says it is working in the background and that its turn is
  over.
- Waiting still comes first: a tab or project with an agent waiting shows the
  waiting triangle.
- The fan-out summary card for a tab no longer appears while one of the tab's
  agents has background work running; it waits until that ends.
- Closing a project that has agents with background work now asks first,
  because closing it stops that work.
- The phone client draws pane rows from the same rule (see Phone).

**Not changed:** a pane with background work still *reads* idle to everything
that acts on it: notifications, waiting and finished detection and closing a
finished pane all use the pane's own status, as before. So a pane can show a
working mark and "N in background" while the agent's turn is over. The help
pages and tooltips now say background work is counted as working.

## Side sheets instead of centred dialogs
The rail's tools (Agents, Worktrees, History, Fan-out history, Todos, GitHub,
API keys, Remote access and Projects) now open as a **side sheet** beside the
rail, from the top bar down, instead of a dialog in the middle of the window.

- There is no dark scrim: the panes stay visible but cannot be used while a
  sheet is open, and a click on them puts the sheet away.
- **Changes** is a wider sheet in a window 1100px or wider, and a dialog
  below that.
- Settings and Help stay dialogs, and Fan out, New todo, Update and Versions
  are dialogs too; the agent picker is a picker at the top.
- A screen opened from another (Worktrees to Changes, Projects to the agent
  picker, a `?` to Help) stacks on it. Escape, × and a new **back** link in
  the header go back one level.
- Closing returns the keyboard to whatever opened the screen, the first
  control in a screen takes the keyboard when it opens, and pressing the key
  that opened a screen closes it again.
- The rail marks the tool that is open.
- The **Go to…** chip is gone from dialog headers. **Go to…** is now an entry
  in the command palette, and also offers Todos, GitHub and Fan out. GitHub
  has a palette entry.
- Narrow windows: a sheet takes the full width at 640px or less, and
  dialogs fill the window.

**Not changed:** what is *inside* each screen. The contents and their wording
are as before; changing them screen by screen follows in later releases.

## Small fixes
- **Keybindings:** an action with no binding is drawn as an ordinary 28px
  button, not a box about 80px tall.
- **Settings tab strip** (windows 640px wide or less, where the sections run
  across the top): Left and Right arrows move between sections, and the
  selected one scrolls to the middle of the strip. At either end of the strip
  a neighbour can still be cut off.
- **Tooltips** go away when you click or press Enter or Space on the control
  they belong to; one still waiting to appear is cancelled.
- **Fan out** no longer reads a permission prompt's options (`1. Yes`,
  `2. No…`) as a plan when it reads a pane's screen. A plan the agent wrote
  out, or a prompt that has been answered, is read as before. "New todo from
  a pane" follows the same rule.

## Wording corrected
The help pages, the README and a few strings in the app described the old
status colours and some behaviour wrongly. Corrected:

- Working is cyan, waiting is an amber triangle, idle is a hollow grey circle,
  a failed pane is a red square and an exited one a hollow square, in the help
  pages, the tooltips and the status line an agent is told about. A Blocked
  row was added to the status table.
- The top bar counts agents across every open project, as the window title
  does.
- The shortcuts page says these are the defaults and can be changed under
  Settings > Keybindings; it names Ctrl+B for the rail as the one key taken
  from programs.
- A worktree with any pane open in it cannot be removed.
- What stays on your machine: the README and help list more of the files
  Flockdeck keeps (`groups.json`, `todos.json`, `worktree-procs.json`,
  `e2e_key.json`, uploads) and the web view's data folder, and the environment
  variables the command line reads.
- **Remote access:** `flockdeck remote -h`, the help and the README now say
  that only the terminal's connection is end to end encrypted, and only when
  both sides have a registered key; the chat view, pane names and state,
  latest replies, pictures, diffs and git actions and API keys typed in the
  window pass through the relay decrypted, over TLS. A fingerprint check exists
  on both sides (Verify on the phone, the Remote access dialog on the desktop).
  This describes what already happened; the product did not change.
- Installing and uninstalling, and the Linux and Helm notes in the README, now
  match what the packages do.
- The Linux binary needs `libgtk-4` and `libwebkitgtk-6.0`; only the Windows
  build is free of them.

## Phone
The phone client (flockdeck-remote v0.2.45) draws a pane from the desktop's
activity, so a pane with background work reads "Working in background" with
the working mark, in the list, the pane header, the chat status line, the page
title and the order of the list. A desktop older than this release sends no
activity and the phone draws from the pane's status as before. A failed pane
is drawn as a filled square. A photo sent from the phone is labelled as sent
through the relay, encrypted on the way (TLS) but not end to end like the
terminal; the offline banner says what you typed is kept and can be sent when
you are back; a few sign-out and waiting labels were made consistent.

## Website and docs
The site and docs wording on encryption, the enterprise relay, the Terms,
Privacy and Trust pages, uninstalling and what the app connects to was
corrected to match the product; "Free and open source" now reads "Free, with
its source available". Docs pages follow at the next regeneration.

Update if you have auto-review on; otherwise nothing needs doing.
