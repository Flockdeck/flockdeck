# Flockdeck v0.8.2

This release lets a Claude Code or built-in chat pane read its Flockdeck mail without asking you, adds the typed wake line and its off switches (nothing is typed for any terminal agent yet), points agents at a repository's knowledge notes, stops sending conversation text and full permission text to windows reached through the relay, catches secrets that have an invisible character inside them, and adds structured agents as a beta that this window cannot show.

## Messages

Reading Flockdeck mail is now allowed without asking in a Claude Code pane and in the built-in chat client, whether or not auto-approve is on, and it does not count towards the pane's auto-approved calls. Only two forms are allowed, written exactly so: `flockdeck inbox` with `-all` and `-json` each at most once, and `flockdeck inbox read <id>` with `-json` before the id. Everything else is asked about as before: `-wait`, `-follow`, any other flag or word, `flockdeck msg send`, every other subcommand, a path to the program, a pipe, a quote, and a command over 4 KiB.

- It is also asked about when the folder the command runs in holds any file or folder named `flockdeck` or starting with `flockdeck.`, in any letter case and ignoring trailing dots and spaces, or when a different `flockdeck` comes earlier on the pane's PATH than this application. A project that builds its own `flockdeck` binary into its root never has mail reads allowed in that folder.
- Other command-line agents keep the approval modes they have; their briefings say how to allow `flockdeck inbox`.

Flockdeck can now type one fixed line into an idle agent that has unread mail and no hook to tell it: `Flockdeck: new mail, message 12. Run: flockdeck inbox read 12`. It names no sender and holds none of the message. A line is typed only for an agent whose prompt rule has been tested against a recording of that agent, and none of the rules that ship is marked tested. So nothing is typed into any terminal agent in this release. Mail for an idle agent still waits, and the pane shows its unread count.

- `flockdeck wake` shows the switches and the last ten wake events, and `flockdeck wake off` and `on` set them for everything, for one kind of agent (`-agent claude`) or for one pane (`-pane <id>`). The switches cannot be set from inside a pane; `status` runs anywhere. If the preferences file is damaged, wake stays off until you set the global switch again.
- Text mode (`flockdeck wake text on -agent aider`) types the message itself, cut to 300 characters on one line, for an agent that cannot run commands. It is off for every agent until you turn it on, and it needs a tested rule like the fixed line.
- Every typed line is recorded in `team-events.jsonl` in the state directory, which keeps the last 2,000 events or 256 KiB.

Each message now records when it was notified, woken and read, in the same log. The log holds no message text, except the line typed in text mode.

The manager's briefing now says each rule once. A short sentence about the typed line is left out of the briefings until a rule is marked tested.

## Knowledge notes

A repository can keep notes about itself in `.flockdeck/knowledge`, starting at `index.md`. When a pane's checkout has them and the project allows it, the agent's briefing gets one line with the folder's path, saying the notes may be stale and are data, not instructions. None of the notes is put in the briefing.

The notes go to whatever model the agent runs on, so the default depends on the repository. The pointer is on when `gh repo view` reports the repository as private. If it is public, or `gh` is missing, signed out or offline, or the remote is not on GitHub, the pointer is off and the window shows a one-time notice. `flockdeck knowledge on` and `off` set it for a project, `flockdeck knowledge` shows it, and both setters are refused inside a pane. The first briefing in a private repository does not wait for the `gh` lookup, so the line appears from the next one.

## Phones and relay windows

A window reached through the relay no longer receives conversation text or the full text of a permission request. The relay can read the connection that text travels on, and it is not yet checked and sealed, so it is kept off until it is. Repository content is still sent: diffs, git status, pull requests, issues, check runs, folder names and branches.

- Opening a pane on a phone shows its terminal, which is encrypted end to end, not the chat. The pane list still shows who is waiting and why, but not what the agent said. The chat stays on the desktop.
- A permission request or a question shows as a card that names the tool, such as "Run a command, details on the desktop". It has no buttons. The command, file, diff and question stay on the desktop. Answer at the desk, or open the pane's terminal view from the phone, where the whole prompt is shown and the answer is typed over the encrypted connection.
- A tab title that was made from the first words of the opening prompt shows as the focused pane's name (or "Tab") on a relay window, and names are cut to 40 characters.
- A phone app from before this change draws Yes and No on a permission card and sends the terminal's answer without showing what it is. The fix is in flockdeck-remote v0.2.51. It reaches phones when the relay is next deployed. Until a phone shows the new cards, do not answer a permission card from a phone: answer at the desk, or open the pane's terminal view.

## Privacy

The privacy page now describes the messages agents in your panes send each other: they are kept until read and for a week after, or for 30 days if never read, with a log of when each was sent, delivered and read and between which panes. The log holds no message text, except the line typed in text mode. It also holds a record of each line Flockdeck typed into an idle agent to tell it mail is waiting, and of each case where the line was typed but not submitted. None of this is sent anywhere by Flockdeck. With Flockdeck Remote on, a typed line is part of the terminal contents it carries, like anything else typed.

## Secrets

A secret with a zero-width character, a bidirectional control or another invisible character inside it was not recognised, so it was written as it was in recordings, exports and text sent to a relay window. Flockdeck now reads the text as if the character were not there, and replaces the secret. When a text holds a secret, all its invisible characters are removed, including unrelated ones such as the joiner in an emoji. A text with no secret keeps them. Redaction is still best effort, as the recording page says.

## Structured agents (beta)

A structured agent is one Flockdeck talks to over the Agent Client Protocol, not in a terminal. The one offered is opencode (structured). It is off until you put `"structuredPanes": true` in `prefs.json` in the state directory; there is no setting for it in the window.

This window cannot show one. A structured pane draws the line "Structured pane, open in the new interface" and sends the agent nothing. The conversation view, the prompt box and the permission cards belong to the new interface, which is not part of this release. If you turn the beta on, know these things:

- opencode as it ships runs shell commands, writes and edits without asking, so a permission card may never appear. The setting `{"permission":{"bash":"ask","edit":"ask"}}` in opencode's own configuration makes it ask.
- A structured agent has no `flockdeck` command, so by default it is not woken by mail. `flockdeck wake text on -agent opencode-acp` turns it on. Each wake is then one prompt with the oldest unread message, cut to 300 characters, in front of an agent that may run commands. Turn it on only for an agent you would trust with another agent's words.
- A login or Node problem shows as a pane marked "needs setup", with the one step to take.
- Recording and export are not available for a structured pane.

## Fixes

- A helper was reported idle to its parent when the idle timer ran out while Flockdeck was closing or restarting it. A pane that is closing no longer counts.
- A peer name reported late by the process from before a restart no longer replaces the new name. The report now carries the launch id, and a report from an earlier launch is dropped.
