# Flockdeck v0.8.0

This release removes Fan out, Todo and Jev routing, stops typing message notices into agent prompts, and adds a help page for running Ornith models.

## Removed

Fan out and Todo are gone: the dialogs, the header and rail buttons, the `Ctrl+Shift+X` binding, the palette entries, the Fan out row in Settings > General and their help pages. To start several agents, use `flockdeck spawn -role <id>` or "Start a team" in the command palette.

- Saved Todo data (`todos.json`) stays on disk and is not read.
- An old `fanOut` preference and old key bindings for these actions are ignored. They do not block a chord.

Jev routing is gone too. The path that sent scrubbed task text to TypeSafe to rate unmatched work has been removed, so routing no longer sends task text anywhere. Status detection in Settings is unchanged.

- If you had turned on "Ask Jev to rate unmatched work", that has stopped. The setting and the Unmatched work table are removed. A saved `"jev": true` is ignored and left in the file, and there is no notice.
- The Suggest routing mode is removed. A saved `"suggest"` loads as off, with a notice on how to turn routing on. Routing now offers Off and Automatic.
- A routing rule with `"kind": "fanout"` is skipped. A warning shows at the top of the agent picker each time `agents.json` is read. The file is not rewritten, so the rule stays flagged until you remove it by hand.
- An old routing record can still be cleared in Settings.

## Messages

Flockdeck no longer types a notice into an agent's prompt when a message arrives. On Windows the notice could be left unsent in the agent's message box.

- A pane header shows "N unread" while messages wait.
- An agent whose hooks are reporting, which includes Claude Code and chat agents, is told in the reply to its next prompt or tool call. An idle agent is told when you next send it a prompt, so a message does not wake it.
- If mail is still unread, the next prompt or tool call more than 5 minutes after the last notice repeats it, up to twice.
- Sender names and roles in a notice are quoted and cut short.
- An agent whose hooks are not reporting gets no notice. Its briefing tells it to run `flockdeck inbox`, and `flockdeck msg send` prints a line when the receiver will not be told.

## Manager and helpers

The manager role now delegates without being asked. Given a goal, it adds tasks to the board, starts a planner, workers, a reviewer, a tester and docs agents, watches their status and reports back.

- `flockdeck spawn -tab "<title>"` puts the new agent in a tab with that title, one tab per task. A later `-tab` with the same title, ignoring case, joins that tab, but only if an earlier `-tab` made it. Tabs you made yourself are never joined. This is not saved, so after a restart the next `-tab` makes a second tab with the same title.
- `flockdeck inbox -wait 90s` waits up to that long (at most 10 minutes) for a message and prints it when it arrives. It does not mark anything read, so run `flockdeck inbox read <id>` afterwards.
- When a helper has finished its turn and stays idle, its parent gets a message in its inbox. Nothing is typed into the parent's prompt.
- An agent can have at most 8 panes open below it. Helpers that started helpers count, and so do helpers whose process has exited until you close the pane.
- Helpers no longer inherit auto review from the agent that started them.
- The manager's briefing tells it to ask you before merging, pushing, opening a pull request, deploying, publishing, deleting or spending money, and to leave those to itself. This is text in the briefing. Flockdeck does not enforce it.

## Paste

Pasting into a pane in the desktop window now removes the same control characters as the remote client and the prompt bar. Tab, line breaks and printable text are kept. A paste that is only control characters sends nothing.

## Security

Browser profile folder names and other secret-folder names are no longer stored as plain text in the Flockdeck binary. The check that refuses a project root inside a folder that keeps secrets works as before, including through links and junctions. A home folder with more than 200,000 entries is now refused as a project root, and a home that cannot be listed is judged by name only. The refusal message now spells the folder the way the path does, so its letter case can differ from earlier releases.

## Added

- A help page on running Ornith models through the openai-compatible agent. Ornith was checked only against a stand-in endpoint, not a live Ornith server.

## Other changes

- The Agents overview and the Team roster draw their pane rows from shared code. Nothing looks or acts differently.
- The privacy and trust pages on the site are updated with this release.
