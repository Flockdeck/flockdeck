# Flockdeck v0.5.0

This release makes the local server refuse requests addressed to an unexpected host name, so reaching Flockdeck by any name other than 127.0.0.1 or localhost now needs a setting, described first. It also makes Flockdeck ask before git runs a program that a repository set up, adds a view-only role for paired devices, and records which paired devices you have verified.

## What to do when you update

- If you open Flockdeck by any address other than `127.0.0.1` or `localhost`, set `FLOCKDECK_ALLOWED_HOSTS` before you update, or you will get a 403 page that names the variable. That covers `[::1]`, a LAN address, a hostname, an Ingress or reverse proxy that passes the original Host header on, a Kubernetes NodePort or LoadBalancer address, and the host's own name under `docker run --network host`.
- The variable is a comma-separated list of host names, for example `FLOCKDECK_ALLOWED_HOSTS=flockdeck.example.com,192.168.1.20 flockdeck -no-window`. `flockdeck.example.com` allows every port, `flockdeck.example.com:8080` allows that port only, IPv6 goes in brackets, and there are no wildcards. A bad entry stops Flockdeck from starting and the message names it.
- The window, the links printed by `-no-window`, `http://localhost:<port>/`, `http://127.0.0.1:<port>/`, and `kubectl port-forward` or `ssh -L` reached through those two names all keep working. A window reached through Flockdeck Remote is not affected.
- The Helm chart sets the variable to the Service's names. If you front the Service with an Ingress, or use a NodePort or LoadBalancer, add that name or address to the new `allowedHosts` value.
- Commit, Push, Pull and Fetch in the review panel can now stop and ask first. The first time Flockdeck sees a repository whose own settings or hooks run a program, it asks once. A husky setup is asked about too, because it looks the same as a hook an agent planted. Details are in the git section below.
- Paired devices have a role now. Every device, new or already paired, stays Full until you change it in the Remote dialog.

## The server checks the Host header

The server now answers a request only when its Host header is `127.0.0.1`, `localhost` (any port) or a name in `FLOCKDECK_ALLOWED_HOSTS`. This stops DNS rebinding, where a web page reached under a name that an attacker later points at 127.0.0.1 could talk to the local server as if it were the same site. The check runs before any handler, including the two WebSocket upgrades.

- A refused request gets a plain 403 that names the variable. Refusals are logged to stderr at most once a minute, with the Host cleaned and cut to 60 characters.
- Names are matched whole and without regard to case or one trailing dot. `localhost.evil.example` is refused. An empty Host, one with a user name, path, space or control character, and a port outside 1 to 65535 are refused.
- `/health` on the loopback names still answers, for the container health check and the check a second launch makes.
- The variable is listed in `flockdeck -h`, in the troubleshooting Help page, in `docs/self-hosting.md` and in the Helm chart's README.

## Git asks before it runs a program

Commit, Push, Pull and Fetch run git as you, and git runs whatever the repository names: hooks, `core.hooksPath`, `core.sshCommand`, a credential helper, a filter or merge driver, a signing program. An agent that can write inside `.git` could set one of these up, and the next press of a button would run it with no agent permission prompt in front of it. Flockdeck now reads what would run and compares it with what you last accepted for that repository.

- When something new would run, a dialog lists each program and the file it comes from. You can cancel, or continue and choose between remembering it for that repository and accepting it just this time.
- It reads the effective git configuration (system, global, repository, included files and a linked worktree's own), the hooks git would find, and the same for each submodule. A remote that is a folder on this machine is listed with the hooks that folder's repository would run on a push.
- A repository where nothing is set to run is recorded without asking, so anything added later counts as a change. A program named only in your own system or global git configuration, such as a credential helper or Git LFS, is not asked about the first time.
- Something Flockdeck cannot read is listed as something it could not check and is never taken to be safe. That covers a hooks folder without permission, a network share, and a limit such as 200 submodules. A scan that does not finish, because git does not answer in 15 seconds for example, is asked about every time and is not remembered.
- A window reached through Flockdeck Remote is never asked. It is told to press the button at the machine.
- Background git no longer runs repository hooks. Status, diff, the index refresh and the conflict radar's scratch index run with `core.hooksPath` turned off, so a `post-index-change` or `reference-transaction` hook no longer runs from them. Commit, push, pull, fetch and creating a worktree still run the repository's hooks.
- The review panel's diff now also passes `--no-textconv`, so a `diff.<driver>.textconv` program is not run to draw a diff.
- Hook names are matched without regard to case on every system. Before, a case-insensitive file system on Linux (vfat, exfat, ntfs, cifs, ext4 casefold) could run `Pre-Commit` for `pre-commit` without it being listed.
- When a scan on a slow repository timed out, the dialog could come back every time even after you chose to continue once. It now reports one item for a timed-out scan, and continuing once is accepted.

The Review, commit and push Help page has the full list of what is read and what is not.

## Paired devices can be limited to viewing

Each paired device is Full or a viewer, and you set it from a button beside the device in the Remote dialog. Full is what every device has had until now and is the default, including for devices paired before this release.

- View artifacts only shuts the device out of everything that exists today. It is sent no panes, tabs, projects, paths or preferences, gets no push notifications, cannot open a terminal, and every command it sends is refused.
- View artifacts and watch panes adds the panes, their chat and their terminal output, and push notifications about waiting agents. It cannot type, resize or run anything.
- Only this machine sets a role. A window reached through the relay is refused, whatever its own role.
- Roles are checked on this machine on every command, message and keystroke. Changing a role ends that device's open connections so it reconnects into the new one.
- A request that names no device, and every device while the table of roles is unknown, is treated as a viewer. If `prefs.json` is damaged at start-up, every device is a viewer until you restart.
- A viewer's window shows a "View only" banner and hides the buttons that start or change things.
- There is no prompt at pairing and no command-line way to set a role yet.

## Paired devices can be marked verified

Each paired device has two end-to-end keys, one for the Flockdeck Remote app and one for the full interface it opens from this machine. The Remote dialog now shows a code for each, six groups of five digits. Compare it by eye with the code the device shows and press Mark verified. A match shows that the key the relay handed out is the key on the device, so it rules out a relay that swapped a key.

- Only this machine can mark a device or remove a mark. A window reached through the relay is refused, and the attempt is written to `error.log`.
- A mark is tied to the device, the key and this machine's own key. If any of them changes the device shows as not verified, or as changed if it was verified before. Unpairing a device from this machine drops its mark.
- Marks are kept in `remote_verified.json` in the state folder. A relay answer with no devices in it does not clear them. Unpairing the last device from its own page can leave a stale mark, which matches nothing.
- Nothing else is limited by a mark yet, except the recordings viewer below.

## Smaller changes

- The README and the website have a recording of Flockdeck in use: three Claude Code agents on three worktrees, the conflict radar firing, Pane info, a baton hand-off and a commit. On the website the file loads only when you press play.
- Flockdeck also listens on a private local channel, a Unix socket in the state folder on Linux and macOS and a named pipe on Windows. It answers two requests, who is running and a one-time window link, and only to the user who started it. Nothing uses it yet, and the command line still connects over the loopback port. If the channel cannot be created, Flockdeck runs without it and says so on stderr and in `error.log`.
- The Windows build now links go-winio (MIT). It is listed in `THIRD-PARTY-NOTICES.md`.
- Remote artifacts has its first parts, and they ship off. A `/ws/artifacts` socket serves windows reached through the relay, and `flockdeck remote artifacts off` closes every such socket and works with no window open. A device can use it only after you switch a kind on, acknowledge the notice, allow the device and verify its key. Only recordings can be switched on, and nothing in the window turns it on yet. An audit log, `remote-artifacts.log` in the state folder, records each connection without content.
- A Desk recordings button for a window reached through the relay reads the desk's recordings in pages, read-only, with the text cleaned and redacted again on this machine first. It stays hidden until the setting above is on, and is never shown on the desk. The recording list skips anything that is not a regular file, so a named pipe called `something.jsonl` no longer holds the listing up.
- Recordings redact more: an unclosed quoted value, names ending in `pass` or `passphrase` such as `DB_PASS`, the flags `--password`, `--token`, `--api-key` and the like followed by a value, `curl -u user:password`, `mysql -ppassword`, `sshpass -p password`, and the credential after an Authorization scheme word. Text over 1 MiB is cut and the rest replaced by one mark. This changes what new recordings contain; files already written do not change.

## Fixes

- The prompt bar removes control characters from text before it sends it to a pane: ESC and the other C0 controls except tab, carriage return and line feed, DEL, and the C1 controls U+0080 to U+009F. Line breaks in a paste still become a carriage return. This replaces the step that removed paste markers from multi-line text.
- A terminal in a window reached through Flockdeck Remote could close with a failed handshake when the desktop's first terminal frame arrived while the key exchange was finishing. Those frames are now held, up to 2048 frames or 8 MiB, and opened in order once the session exists.
- A helper app install no longer tells you the trust record is damaged when it could only not be read just now, for example because another program had it open on Windows. It says it could not be read and to try again. A file that was read and does not parse still says it is damaged.
