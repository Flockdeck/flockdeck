# Flockdeck v0.9.4

This release fixes a pane that stayed on "working", makes closed team tabs stay closed, keeps agents from closing panes in other projects, and adds a second approval option to the plan card.

## Plan card

The plan card for a plan an agent asks you to approve now has three options: Approve and ask before edits, Approve and accept edits, and Reject. The first is the old Allow, and the mode went back to ask-before-edits after it. Approve and accept edits answers allow and switches the session to accept-edits mode at once. If Claude reports a different mode at the start of its next turn, that report replaces it.

Plan cards stay on the desk. A phone cannot answer one, because both approve options are single-use and a plain Allow from a phone would be refused as ambiguous. Codex has no plan approval request, so it is unchanged.

## A pane stuck on "working"

A tool event could arrive after a turn had ended and after Claude Code's idle nudge, and its matching done event never came, for example because the call was refused or the hook gave up. Nothing then ended the working status, and the pane stayed marked working at an empty prompt. A pane in that state now settles to idle after 10 seconds with no hook events and no output. A tool that is still drawing its clock keeps the pane working.

This matches a report of a manager pane that showed working with no background work counted. It was not confirmed against that pane's own events.

## Closed team tabs

Closing a team tab stores its goal id in a preference shared by all projects. Any tab change made in another project rewrote that list and dropped the ids that project did not know about, so closed tabs came back when you switched to the first project again. The list now keeps those ids, up to 200.

## Closing panes across projects

`flockdeck close <pane-id>` now refuses a pane that belongs to another project, and `flockdeck close -finished` closes only the finished panes of the caller's project. Before, `close -finished` closed idle panes in every project. The relay team view, the All agents overview and the window's own Close finished command are unchanged on purpose, because they are views the person at the window controls.

Messaging by id, name or role, `pane-name -pane`, the roster, the task board and team, `spawn -baton` and the team graph were already limited to their own project. This release adds tests for them.

## What was and was not tested

The Go tests for the touched packages and the UI tests for the goal tabs passed in CI on Linux, Windows and macOS. The full package suites were not run on the machines that wrote the changes, because they ran out of memory there, so CI was the first full run. Approve and accept edits was tested against a fake Claude only. Nothing checked that a real Claude applies the mode change on an approval.
