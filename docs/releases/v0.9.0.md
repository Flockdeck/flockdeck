# Flockdeck v0.9.0

This release replaces the tiled window with the team graph window, starts new Claude Code and opencode panes as structured panes, removes `flockdeck chat` and the API agents, tells a paired phone when a structured agent is waiting, and fixes a batch of security and bug-search findings.

## A new window

The window is now the team graph. Panes are nodes in a graph of who is working with whom, what each is doing and what is waiting on you. A pane opens in a drawer with its terminal or its conversation, a Changes tab, its task and its worktree. The old tiled window is gone: this release does not have it.

- The Team view shows the team as an outline with decision blocks (a stuck helper, a deadlock, an overlap between two branches, a request waiting on you), a goal line, and a feed of what happened. Goal tabs replace the terminal tab strip. A Dependencies view shows work by what blocks it.
- The Changes view lists the branches of the whole team. It has a diff viewer with review comments, the merge gate (approve, unapprove, merge), and running a project's checks after you confirm the commands.
- Panes have labels. `flockdeck spawn -name <label>` and `flockdeck pane-name` set one, and an agent's briefing tells it to label its pane for the work.
- A helper started in a role that works on its own branch (worker, tester, docs, or no role) gets its own worktree and branch by default. `-worktree <branch>` names the branch and `-no-worktree` uses the shared checkout. A project that is not a git repository refuses the start and says so.
- `promote` makes a running solo agent the manager. It refuses when the project already has one.
- Settings has a Typed wake section. The drawer has a message box on terminal panes, and a conversation shows mail as message entries.
- The shortcut Ctrl+Shift+U opens the drawer and Ctrl+Shift+J goes to the previous agent that needs you.

The control socket API is at version 1.28. A window that sends a command the server does not know is told it is unsupported.

## Removed: flockdeck chat and the API agents

`flockdeck chat` and the agents that ran on it are gone (#705, API 1.15): Anthropic, OpenAI, Google and OpenAI-compatible endpoints. This is a breaking change. An `agents.json` entry that sets `api`, or that names one of the removed built-ins, is dropped with a notice. The command `setAgentAddress` and the message `agentAddress` are removed, and a server answers `setAgentAddress` as `unsupported`. The per-token model prices left the agent list too. Use a command-line agent such as Claude Code, Codex or Gemini CLI. `flockdeck keys` stays: a key you store is given to a structured agent that takes one.

## Structured panes are the default for new Claude Code and opencode panes

A new pane of Claude Code or opencode now starts as a structured pane: Flockdeck drives the agent over the Agent Client Protocol and the drawer shows the conversation, instead of running the agent's terminal. In v0.8.2 this was a beta that the window could not show.

This changes new panes only. A saved layout restores each pane as it was, so a terminal pane is still a terminal pane.

On a machine with paired devices or remote access turned on, new panes stay terminal by default. A phone is told when a structured agent is waiting ("Answer on the desktop") but cannot answer it yet, and phone Allow and Deny are not offered until the phone app ships. Settings, General, "New panes start as" overrides the default either way.

Going back to a terminal:

- Settings, General, "New panes start as": Terminal (the `panes` command, API 1.28). Running panes are not ended.
- `flockdeck spawn -terminal` starts the terminal version of an agent from the command line.
- The picker lists both. The terminal entries are named "Claude Code (terminal)" and "opencode (terminal)".
- A structured pane that failed to start, needs signing in or whose agent ended has a "Restart as terminal" button. The pane keeps its place and folder; the conversation starts afresh.

Agents with no route over ACP stay in a terminal: Cursor Agent, Aider, plain shells, and any CLI you added in `agents.json`. An `agents.json` entry that reuses a built-in terminal id runs as written. Codex and Gemini CLI stay terminal too, for now. Their structured entries are hidden until they have been run against the real programs.

What a structured pane does not do yet:

- A phone cannot answer a permission request. It gets a notification that says to answer on the desktop.
- Rewind takes back the conversation, not the files the agent changed. File rewind is not built.
- "Always allow" lasts for the session. After a pane restarts the agent asks again, and Flockdeck restarts panes on update.
- Agents get mail as prompts and send with `send_message` and `list_peers`. `flockdeck msg`, `inbox` and `wake` work in terminal panes only.
- A structured pane is not recorded.

Signing in: a Claude Code pane that is not signed in shows "needs setup". Open Agent info, press Sign in, and Flockdeck starts Claude's own login and restarts the pane when it ends. Flockdeck never sees the password or key. The API keys dialog no longer has a row for Claude Code (structured); `keys set` still works for it.

Project trust: in a folder you have not told Claude Code to trust, the adapter does not apply the project's allow rules, and the pane says so. Open the folder in a terminal pane once and accept the trust prompt, or use the permission cards.

Also in this release for structured panes: forking a conversation after a rewind works with the session file Claude keeps, the plan checklist draws from Claude's task tools, and a pane runs shell commands typed after `!`.

## Phones

A paired device that gets pushes is now told "Answer on the desktop" when a structured pane waits. The push carries no card text. Phone approval is switched off in this release: while it is, no push says "Allow or deny", `approveChallenge` and `setDeviceApprove` (on) are refused, and the Remote page does not offer the "Approve: off" button. Turning approval off still works.

Two push fixes: a push that failed to reach the relay is now retried (before, the phone was never told of that wait), and a push goes to every opted-in device, not only the first 32.

## Security fixes

From the 8 October bug search (#760):

- `flockdeck recordings` prints a list without control characters.
- portproxy has an idle timeout and closes a silent client once Flockdeck is done.
- A baton start is judged against the agent and folder it will run in, and a stored baton loads under the id it was asked for.
- The strict command profile drops PowerShell environment assignments, and a baton scrubs the value of a PowerShell `env:` assignment whose name looks like a secret.
- Auto-review checks a `revision:path` argument for secret names, asks about a recursive grep, finds submodules in the whole repository, and treats plural key names such as `accessKeys` and `api_keys` as secret file names.
- A pane id that is not safe in a file name is refused when a layout is restored, and a saved key binding must be a well-formed chord.
- Relay close reasons are cleaned like the other relay strings.

Spawn routing now reads the routing policy and default agent from the project's root, so a pane in a subfolder or linked worktree is routed like any other (#744). A link whose text looks like a host shows the real destination, and more invisible characters are cleaned from names shown on a relay window.

## Fixes from the digests

- `keys set` decodes UTF-16 input (a key piped from PowerShell 5.1's `>` redirection) and refuses other input with a NUL byte. It runs under a lock, so two copies no longer overwrite each other's keys. On the Windows release, which has no standard input unless one is piped, it says to pipe the key or use Settings.
- A script run with standard input from `/dev/null` or `NUL` now gets the error it should, not a prompt.
- `flockdeck update -version 1.4.0` works without the leading `v`.
- `remote delete-account` gives the delete its own 30 seconds after you have read the summary and typed the phrase.
- Commit waits up to 60 seconds for Flockdeck's own index refresh on a large checkout, and no refresh starts while a commit is waiting. Before it failed on a lock error after 3 seconds.
- A Claude pane follows a resumed conversation to its newer transcript copy, and an open replacement transcript is not swept by another instance.
- Two instances sharing the state folder no longer undo each other's records in the worktree process registry. Baton prune looks again just before it removes one.
- Help pages show the key you have set, not the built-in default.
- The server's quit, restart, detach and last-window hooks are passed in at start, which removes a data race.
- A late resize or keystroke frame no longer leaves a stale terminal size entry after a viewer leaves.
- The CLI usage text and the `cli` help page list every subcommand.

## What is missing

These are things the old window did that the new one does not, and they are chosen, not forgotten:

- The GitHub view (pull requests, issues, check runs). Use `gh` in a terminal pane for now.
- Recording a structured pane. Terminal panes record as before.
- A team view in the phone app. The phone still shows the roster.
- The tips bar.
- Tiling, splitting, moving and broadcasting to panes. A team is a graph, and a manager sends to its team.

## What was and was not tested

The test workflow runs the suite on Linux, Windows and macOS. The notes for the new window said it was run by hand on Windows only, not on Linux or macOS, and that no real phone was paired through the relay to it. That has not been rechecked for this release.

The page is larger than the old plan assumed. On the first-load model in `docs/first-load.md` (a 1.6 Mbit/s link, 150 ms round trip, CPU slowed four times) the shell takes about 10 seconds to a first meaningful paint, against a 3 second budget. That model is a guess at a mid-range phone, and the real number needs a real phone.
