# Flockdeck v0.8.1

This release adds `flockdeck inbox -follow` so an idle agent can be woken by mail, briefs agents to message each other with SendMessage, shows the real release notes in the update chip, describes the lens helper download in the privacy and trust pages, and fixes a crash on Windows.

## Messages

An agent that has ended its turn can now be woken by a message. `flockdeck inbox -follow` prints one line for each new unread message, with its id and the sender in quotes but not the message, and marks nothing read. In Claude Code, the Monitor tool runs it and turns each line into a new turn, so the agent reads the message with `flockdeck inbox read <id>`. Flockdeck still types nothing into an agent's prompt.

- The briefings tell every agent that can call back into Flockdeck to start the stream once at the start of its work, and to start it again when the Monitor tool's timeout (at most 30 minutes) ends it. An agent that forgets keeps the notice on its next prompt or tool call and the unread count on its pane.
- The Monitor tool is not available on Bedrock, Vertex or Foundry, or with telemetry turned off. There the briefing falls back to `flockdeck inbox -wait 90s`, run as a background command and started again each time it exits.
- A burst of mail is held for 5 seconds between lines, and more than three messages from agents arrive as one line. A message from you is always on a line of its own and is never held. After 100 lines of agents' messages the stream announces only yours.
- The stream ends when its pane is closed, and after two minutes of errors from Flockdeck. Starting it again announces any messages that are still unread.
- Only Claude Code is known to be woken this way. Codex, Gemini CLI, opencode, Aider and Cursor Agent were not checked in a live pane; their briefings still tell them to run `flockdeck inbox` at the start, after each step and before they report.

Agents are now briefed to message each other with the SendMessage tool, by the session name that ListAgents shows, and only with that tool between agents. `flockdeck msg send` stays as the fallback for when SendMessage fails or an agent has no such tool. Flockdeck's own notices (a helper went idle or exited, a task changed) still arrive in the inbox.

- The manager hands each helper its own session name in the helper's task and looks the helpers' names up in ListAgents.
- A manager that is idle may not be woken by a helper's SendMessage. A manager that has started the stream is woken by the helper's idle notice, which arrives in its inbox.

## Updates

The update chip now shows the release notes written for this version. Before, the signed manifest carried the titles of the pull requests in the release. A release that is not a release candidate and has no notes file now stops the build instead of falling back to those titles. Release candidates still use generated notes.

## Privacy

The privacy policy and the trust page now describe the optional lens helper download. If you install lens (Helper apps in the command palette, or `flockdeck helpers install lens`), Flockdeck fetches it from dl.flockdeck.ai/lens and from no other address, checks the signatures and the SHA-256 and size before it unpacks anything, and asks you first unless you pass `-yes`. While the Helper apps dialog is open, and when you run `flockdeck helpers list -check`, it asks the same address whether a newer version exists, and downloads it only when you confirm. The request sends the user agent `flockdeck-helpers`, and the server sees your IP address, as with any download. The update setting does not turn this off; not installing lens does. The command line help page carries the same facts.

## Fixes

- Windows: a folder read that took too long while Flockdeck scanned a project could end Flockdeck with a nil pointer error when the scan moved on and closed the folder. The handle is now closed when the read returns.
